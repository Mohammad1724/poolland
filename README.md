## چرا پول‌لند؟

اگر می‌خواهی خرج‌های روزمره را مرتب ثبت کنی یا VPN می‌فروشی، حتماً این‌ها برایت آشناست:

- «این ماه خرج خوراک و رفت‌وآمدم چقدر شد؟ از بودجه‌ام چقدر مانده؟»
- «فلانی ۵۰۰ هزار بدهکاره، دو ماهه نمی‌ده…» 🙄
- «کی سرویسش تموم می‌شه؟ یادم رفت تمدید کنم.»
- «این ماه چقدر فروختم؟ چقدر خرج سرور و تبلیغات شد؟ اصلاً سود کردم یا نه؟»
- «مشتری خارجی با تتر حساب می‌کنه، چطور با فروش تومانی قاطی نشه؟»

پول‌لند دقیقاً برای همین‌ها ساخته شده — یک دفتر ساده برای امور شخصی و فروش VPN، نه یک نرم‌افزار حسابداری پیچیده. دفتر شخصی و کسب‌وکار از هم جدا می‌مانند.

## ✨ قابلیت‌ها

### 👤 مدیریت مالی شخصی (صفحهٔ آغازین)
- ثبت سریع **هزینه و درآمد شخصی**؛ اطلاعات از دفتر کسب‌وکار VPN جدا می‌ماند
- خلاصهٔ ماهانهٔ درآمد، هزینه و خالص ماه
- بودجهٔ ماهانه برای دسته‌هایی مثل خوراک و رفت‌وآمد، همراه با نمایش میزان مصرف
- تراکنش‌های تکرارشونده برای اجاره، حقوق، اینترنت و قبض‌ها
- نمودارهای روزانه، هفتگی و ماهانه و دسترسی مستقیم به تراکنش‌های اخیر

### 👥 مدیریت مشتری‌ها و حساب‌ها
- ثبت مشتری با نام، شماره تماس، آیدی تلگرام و یادداشت
- **بدهکار / بستانکار** هر مشتری، همیشه جلوی چشم
- ثبت **بدهی یا طلب قبلی** برای شروع از وضعیت فعلی
- فیلتر سریع «بدهکاران» و «بستانکاران» + جست‌وجو
- دکمه‌ی تماس، تلگرام و کپی خلاصه‌ی حساب
- **صورت‌حساب PDF** برای هر مشتری، آماده‌ی ارسال

### 🔑 اشتراک‌ها و تاریخ انقضا
- ثبت فروش اشتراک با تاریخ شروع و پایان (تقویم **شمسی**)
- پلن‌های آماده: «۱ ماهه ۵۰ گیگ»، «۳ ماهه نامحدود» و…
- هشدار خودکار **سرویس‌های نزدیک انقضا** و منقضی‌شده
- تمدید **یک‌کلیکی**: اشتراک جدید از فردای تاریخ پایان ساخته می‌شود
- نوار پیشرفت عمر سرویس و تعداد روزهای باقی‌مانده

### 💵 حسابداری و سود واقعی
- چهار نوع تراکنش: **درآمد**، **هزینه**، **دریافت از مشتری**، **پرداخت به مشتری**
- ثبت **نسیه یا نقدی** برای هر فروش/هزینه
- دسته‌بندی درآمد و هزینه (خرید سرور، دامنه، تبلیغات، حقوق، …) و امکان ساخت دسته‌ی دلخواه
- گزارش **سود = درآمد − هزینه − برگشت وجه**
- **موجودی صندوق** (نقد + بانک) با جریان نقدی واقعی
- تراکنش‌های دوره‌ای برای هزینه‌های سرور، اینترنت، اجاره یا حقوق

### 💱 چند ارزی
- تومان (پایه) + دلار، تتر، یورو و **هر ارزی که خودت اضافه کنی**
- هر تراکنش **نرخ تبدیل خودش** را ذخیره می‌کند (اسنپ‌شات)، پس گزارش‌های قدیمی با تغییر قیمت دلار خراب نمی‌شوند
- نمایش بدهی هر مشتری **به تفکیک ارز** (مثلاً ۲۰ دلار بدهکار + ۵۰۰ هزار تومان)

### 📩 خواندن پیامک‌های بانکی (فقط اندروید)
- پیامک‌های بانکی را می‌خواند و **واریز / برداشت / خرید** را تشخیص می‌دهد
- **تبدیل خودکار ریال به تومان** (مبالغی که بانک به ریال می‌فرستد، درست وارد دفتر می‌شوند)
- پوشش بانک‌های اصلی: ملت، صادرات، تجارت، ملی، پارسیان، سامان، پاسارگاد، آینده،
  رسالت، سینا/بلو، کشاورزی، رفاه، شهر، دی، گردشگری، سپه، پست‌بانک، ایران‌زمین و…
- **فقط پیامک‌های شناخته‌شده**: پیامک باید با قاعدهٔ داخلی بانک یا قاعدهٔ سفارشی شما تطبیق کند؛ پیامک‌های ناشناخته وارد صف نمی‌شوند. پس از افزودن قاعدهٔ سفارشی، برای بررسی دوبارهٔ پیامک‌های قبلی از «اسکن دوباره» استفاده کنید
- **صف بررسی اجباری**: هر پیامکِ پذیرفته‌شده پیش از ثبت نیازمند تأیید است؛ ابتدا حوزهٔ کسب‌وکار VPN یا شخصی را انتخاب می‌کنید، سپس نوع و دسته‌بندی را بررسی می‌کنید
- **تطبیق خودکار مشتری**: اگر ۴ رقم آخر کارت یا شماره کارتِ مشتری را در پروفایلش بنویسید، واریزهای او با مشتری تطبیق داده می‌شوند؛ انتخاب حوزه همچنان دستی است
- فیلتر هوشمند پیامک‌های غیرمالی (رمز یک‌بار مصرف، کد تأیید، اعلان موجودی…)
- تنظیم بازهٔ بررسی (پیش‌فرض: ۹۰ روز گذشته)

> **نکته‌ی مهم:** خواندن پیامک فقط روی **اندروید** کار می‌کند و در نسخه‌ی وب غیرفعال است.
> پیامک‌ها فقط روی خودِ گوشی خوانده می‌شوند و هیچ داده‌ای به جایی ارسال نمی‌شود.

### 📊 گزارش‌ها و خروجی
- نمودار درآمد/هزینه‌ی ۶ ماه اخیر
- نمودار دایره‌ای هزینه‌ها به تفکیک دسته
- برترین مشتری‌ها و منابع درآمد
- بازه‌های آماده: این ماه، ماه قبل، ۳ ماه، ۶ ماه، امسال، همه
- خروجی **PDF** گزارش دوره، و **CSV (اکسل)** تراکنش‌ها و مشتری‌ها

### 🔒 حریم خصوصی و پشتیبان
- **۱۰۰٪ آفلاین** — بدون حساب کاربری، بدون سرور، بدون اینترنت
- همه‌ی داده‌ها فقط روی دستگاه خودت (Hive، بدون نیاز به SQLite)
- **پشتیبان‌گیری JSON** و ارسال با تلگرام/واتس‌اپ/ایمیل یا ذخیره در گوشی
- **بازگردانی** با انتخاب فایل پشتیبان
- **قفل برنامه با رمز عددی** (۴ تا ۸ رقم) از بخش تنظیمات ← امنیت، به‌همراه **باز کردن با اثر انگشت**
- حالت تاریک / روشن / سیستم + اعداد فارسی
- برنامه‌ی **حسابداری کاملاً فارسی و راست‌به‌چپ** با تقویم شمسی

## نصب و اجرا

### ۱) نسخه‌ی آماده‌ی اندروید (APK)
آخرین نسخه را از صفحه‌ی **[Releases](../../releases/latest)** دانلود کن:

| فایل | مناسب برای |
|---|---|
| `poolland-vX.X.X-arm64-v8a.apk` | **۹۵٪ گوشی‌های امروزی** (سبک‌ترین و پیشنهادی) |
| `poolland-vX.X.X-armeabi-v7a.apk` | گوشی‌های قدیمی‌تر ۳۲بیتی |
| `poolland-vX.X.X-universal.apk` | همه‌ی گوشی‌ها (حجم بیشتر) |

> روی گوشی، نصب از منابع نامعتبر (Install unknown apps) را برای مرورگر یا فایل‌منیجر فعال کن.
> هر بار تگ جدید (`v1.x.x`) بزنی، GitHub Actions خودش APK می‌سازد و در Releases می‌گذارد.

### ۲) ساخت از سورس
```bash
# پیش‌نیاز: Flutter 3.4x به بالا
git clone https://github.com/Mohammad1724/poolland.git
cd poolland
flutter pub get
flutter run                    # اجرا روی گوشی/شبیه‌ساز
flutter build apk --release    # ساخت فایل APK
```

### ۳) امضای نسخه‌ی release (مهم)

به‌صورت پیش‌فرض، اگر هیچ کلیدی تنظیم نشده باشد، بیلد release با **کلید debug** امضا می‌شود تا `flutter run --release` روی یک کلون تازه کار کند. ولی کلید debug روی هر ماشین فرق دارد، یعنی:

- کاربری که نسخه‌ی قبلی را دارد، موقع نصب آپدیت خطای **«App not installed»** می‌گیرد،
- و آن APK هیچ‌وقت قابل انتشار در Google Play نیست.

برای بیلدهای واقعی یک کلید بساز (یک بار برای همیشه — **حتماً ازش بکاپ بگیر**؛ اگر گمش کنی دیگر نمی‌توانی برای کاربران فعلی آپدیت بدهی):

```bash
keytool -genkey -v \
  -keystore ~/poolland-release.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias poolland
```

**بیلد محلی:** فایل `android/key.properties.example` را به `android/key.properties` کپی کن و پرش کن. این فایل در `.gitignore` هست و هیچ‌وقت کامیت نمی‌شود.

**بیلد روی GitHub Actions:** کلید را base64 کن و به‌همراه رمزها در Secrets بگذار:

```bash
base64 -w0 ~/poolland-release.jks   # روی مک: base64 -i ~/poolland-release.jks
```

در **Settings → Secrets and variables → Actions** این چهار Secret را بساز:

| نام Secret | مقدار |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | خروجی دستور بالا |
| `ANDROID_KEYSTORE_PASSWORD` | رمز keystore |
| `ANDROID_KEY_ALIAS` | `poolland` |
| `ANDROID_KEY_PASSWORD` | رمز کلید |

بعد در `.github/workflows/release.yml`، **قبل از** مرحله‌ی `Build split APKs` این مرحله را اضافه کن:

```yaml
      - name: Decode release keystore
        env:
          KEYSTORE_BASE64: ${{ secrets.ANDROID_KEYSTORE_BASE64 }}
        run: |
          if [ -z "$KEYSTORE_BASE64" ]; then
            echo "::error::ANDROID_KEYSTORE_BASE64 is not set — refusing to ship a debug-signed APK."
            exit 1
          fi
          echo "$KEYSTORE_BASE64" | base64 -d > "$RUNNER_TEMP/poolland-release.jks"
```

و به هر دو مرحله‌ی build این `env` را بده:

```yaml
        env:
          POOLLAND_KEYSTORE_PATH: ${{ runner.temp }}/poolland-release.jks
          POOLLAND_KEYSTORE_PASSWORD: ${{ secrets.ANDROID_KEYSTORE_PASSWORD }}
          POOLLAND_KEY_ALIAS: ${{ secrets.ANDROID_KEY_ALIAS }}
          POOLLAND_KEY_PASSWORD: ${{ secrets.ANDROID_KEY_PASSWORD }}
```

Gradle همین چهار متغیر محیطی را می‌خواند (یا `android/key.properties` را، اگر وجود داشته باشد). اگر هیچ‌کدام نبود، با کلید debug امضا می‌کند و در لاگ بیلد هشدار می‌دهد.

### ۴) نسخه‌ی وب (قابل نصب روی گوشی مثل اپ)

## شروع سریع

۱. در اولین اجرا، نام کسب‌وکار و **موجودی اولیه صندوق** را وارد کن
۲. مشتری‌ها را اضافه کن (بدهی قبلی هر کس را هم می‌توانی وارد کنی)
۳. پلن‌های فروشت را در «تنظیمات ← پلن‌های فروش» بساز
۴. از دکمه‌ی ➕ هر فروش را ثبت کن؛ بقیه‌ی حساب‌ها خودکار به‌روز می‌شوند
۵. برای امتحان سریع، در خوش‌آمدگویی گزینه‌ی **«اول با داده‌ی نمونه امتحان کنم»** را بزن

> می‌خواهی ببینی چطور کار می‌کند؟ همین حالا با داده‌ی نمونه امتحان کن، بعد از «تنظیمات ← پاک کردن همه‌ی داده‌ها» از صفر شروع کن.

## منطق حسابداری (قرارداد علامت‌ها)

| وضعیت | معنی |
|---|---|
| مانده **مثبت** | مشتری **به تو بدهکار** است |
| مانده **منفی** | **تو به مشتری بدهکار**ی (پیش‌پرداخت یا اضافه‌پرداخت) |
| تراکنش **نقدی** | روی صندوق اثر دارد |
| تراکنش **نسیه** | روی حساب مشتری اثر دارد |

- **سود** = درآمدِ دریافت‌شده − هزینه − برگشت وجه
- **موجودی صندوق** = موجودی اولیه + فروش‌های نقدی + وصولی‌ها − هزینه‌های نقدی − پرداخت‌ها
- فروش نسیه در حساب مشتری به‌عنوان طلب ثبت می‌شود، اما تا وقتی پولی دریافت نشده وارد درآمد و سود نمی‌شود.
- مجموع خرید در پروفایل مشتری فروش کامل را نشان می‌دهد؛ درآمد و سود گزارش‌ها فقط بر مبنای مبلغ وصول‌شده‌اند.
- با هر پرداخت مشتری، همان مبلغِ دریافت‌شده به درآمد اضافه و از بدهی او کم می‌شود؛ پرداخت‌های بعدی هم به همین شکل ثبت می‌شوند.
- **برگشت وجه** پولی است که از صندوق خارج می‌شود: سود و موجودی صندوق را کم می‌کند، ولی مانده‌ی حساب مشتری را جابه‌جا نمی‌کند. (اگر مشتری تسویه کرده و پولش را پس بدهی، مانده‌اش صفر می‌ماند — نه منفی.)

## ساختار پروژه

```
lib/
├── core/
│   ├── sms/             # موتور خواندن پیامک بانکی (پارسینگ خالص + کانال اندروید)
│   │   ├── sms_parser.dart   # تشخیص مبلغ، ریال/تومان، جهت، کارت، پیگیری
│   │   ├── bank_rules.dart   # قوانین بانک‌های ایران (قابل توسعه)
│   │   ├── sms_models.dart   # SmsMessage و ParsedSms
│   │   └── sms_service.dart  # ارتباط با اندروید (MethodChannel)
│   └── ...             # ابزارها: قالب‌بندی اعداد و تاریخ شمسی، ارز، پشتیبان‌گیری
├── data/            # مدل‌ها، منطق حسابداری، دیتابیس (Hive)، گزارش PDF
│   ├── models.dart      # Customer, Subscription, Plan, Txn, Category, Settings
│   ├── ledger.dart      # محاسبات خالص: مانده، سود، سری ماهانه، وضعیت اشتراک
│   ├── repository.dart  # عملیات برنامه (فروش، تمدید، دریافت، …)
│   └── pdf_service.dart # گزارش و صورت‌حساب PDF با فونت فارسی
└── ui/              # رابط کاربری
    ├── dashboard_page.dart      # داشبورد خلاصه
    ├── customers_page.dart      # فهرست و پروفایل مشتری
    ├── subscriptions_page.dart  # اشتراک‌ها و انقضا
    ├── transactions_page.dart   # دفتر تراکنش‌ها
    ├── reports_page.dart        # گزارش‌ها و خروجی‌ها
    ├── settings_page.dart       # تنظیمات، ارزها، دسته‌ها، پشتیبان
    ├── sms_page.dart            # صف بررسی پیامک‌های بانکی
    ├── forms/                   # فرم‌های ثبت
    └── widgets/                 # ویجت‌های مشترک و نمودارها
```

**نکته‌ی معماری:** همه‌ی محاسبات حسابداری در `ledger.dart` به‌صورت **تابع خالص** نوشته شده‌اند؛
یعنی بدون رابط کاربری و بدون دیتابیس قابل تست هستند.
همین‌طور موتور پیامک بانکی (`core/sms/sms_parser.dart`) کاملاً خالص است؛
تست‌های حسابداری، پیامک و رندر صفحه‌ها در پوشهٔ `test/` قرار دارند.

## حریم خصوصی

پول‌لند **هیچ داده‌ای را جایی نمی‌فرستد**. نه آنالیتیکس دارد، نه تبلیغات، نه سرور.
همه‌ی اطلاعات در دیتابیس محلی روی گوشی خودت ذخیره می‌شود و با فایل پشتیبان JSON می‌توانی آن را منتقل کنی.

### قفل برنامه

از **تنظیمات ← امنیت** می‌توانی یک رمز عددی ۴ تا ۸ رقمی بگذاری. بعد از آن:

- موقع باز شدن برنامه رمز پرسیده می‌شود.
- اگر برنامه بیشتر از یک دقیقه در پس‌زمینه بماند، موقع برگشتن دوباره قفل می‌شود. (این یک دقیقه عمدی است تا وقتی برای انتخاب فایل پشتیبان یا صدای اعلان از برنامه خارج می‌شوی، وسط کار رمز نپرسد.)
- بعد از باز کردن قفل دقیقاً به همان صفحه‌ای برمی‌گردی که بودی؛ حتی فرم نیمه‌پرشده از بین نمی‌رود.

#### باز کردن با اثر انگشت

اگر روی گوشی‌ات اثر انگشت یا چهره ثبت کرده باشی، بعد از فعال کردن رمز عددی یک گزینه‌ی دوم هم در همان بخش امنیت ظاهر می‌شود. با روشن کردنش، صفحه‌ی قفل خودش پنجره‌ی اثر انگشت را باز می‌کند و با یک لمس وارد برنامه می‌شوی.

- این گزینه **فقط وقتی نشان داده می‌شود** که گوشی حسگر داشته باشد و حداقل یک اثر انگشت روی خود اندروید ثبت شده باشد.
- اثر انگشت **جایگزین رمز عددی نیست، میان‌بر آن است.** هر وقت بخواهی می‌توانی پنجره را ببندی و رمز را دستی وارد کنی؛ اگر حسگر هم خراب باشد یا چند بار اشتباه بخوانَد، صفحه‌کلید رمز سر جایش هست.
- با **خاموش کردن رمز عددی، اثر انگشت هم خودبه‌خود خاموش می‌شود**؛ چون چیزی برای باز کردن باقی نمی‌ماند.
- این تنظیم هم مثل خود رمز **داخل پشتیبان ذخیره نمی‌شود** و مال همین گوشی است.
- اثر انگشت‌ها را خودِ اندروید نگه می‌دارد؛ پول‌لند هیچ‌وقت آن‌ها را نمی‌بیند و فقط یک جواب «درست/نادرست» از سیستم‌عامل می‌گیرد.

چند نکته که بهتر است بدانی:

- رمز به‌صورت **هش SHA-256 با salt تصادفی** ذخیره می‌شود؛ خودِ رمز هیچ‌جا نوشته نمی‌شود.
- این قفل جلوی **رابط کاربری** را می‌گیرد، نه فایل دیتابیس را. دیتابیس Hive رمزنگاری **نشده** است؛ یعنی کسی که به فایل‌های داخلی گوشی (مثلاً با روت) دسترسی داشته باشد همچنان می‌تواند داده‌ها را بخواند. هدف این قفل، محافظت در برابر «گوشیِ دستِ دیگران» است.
- رمز و تنظیم اثر انگشت **داخل فایل پشتیبان ذخیره نمی‌شوند** و بازگردانی پشتیبان هم قفل این گوشی را عوض نمی‌کند. قفل مال این دستگاه است، نه مال داده‌ها.
- **اگر رمز را فراموش کنی راه بازیابی وجود ندارد.** حتماً از داده‌هایت پشتیبان بگیر.
